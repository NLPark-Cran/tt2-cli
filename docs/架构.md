# 架构

## 总览

```
用户 Agent ──tt2 CLI──▶ cli.tt2.li/api (FastAPI) ──Redis 队列──▶ 猹询码 worker
                                                              │ glm-5.3-flash
                                                              ▼
                                                        TokenDance 网关
人类浏览器 ──▶ free.hub.tt2.li (Astro 静态) + /api 反代             │
                                                              ▼ 部署（rsync+SSH）
                                                     边缘节点 Caddy（自动 HTTPS）
```

## 信任边界

| 层 | 能做什么 | 不能做什么 |
|---|---|---|
| 用户 Agent | 调 tt2 CLI / 公开 API | 任何直连服务器的通道 |
| tt2-api | 认证、配额、任务管理、部署执行 | 不做内容判断 |
| 猹询码 worker | 白名单工具（读暂存区/文本修补/部署/反问） | shell、网络、暂存区外的文件 |
| 边缘节点 | Caddy 发静态文件 | 无解释器、无用户进程 |

## 关键流程

1. **设备码登录**：CLI `POST /auth/device` → 浏览器确认 → CLI 轮询取 token（一次性）。
2. **TokenPay**：控制台发起 TokenDance 授权（PKCE S256）→ code 换 Key → Fernet 加密落库。
3. **部署**：上传 tar.gz（防逃逸校验）→ 任务入队 → 猹询码审查/适配 → `deploy` 工具触发服务端 rsync + Caddy 片段 + reload。
4. **计费降级**：用户 Key 报 `TokenDance-Recovery-Action` → 尝试共享免费池（平台 Key + 全局限额）。
5. **自备域名**：登记 → DNS 指南 → `check` 确认解析 → 并入 Caddy 站点地址列表 → 自动出证书。

## 证书

边缘节点 Caddy 对每个显式配置的域名自动走 HTTP-01/TLS-ALPN-01 签发 Let's Encrypt 证书并自动续期。只有注册过的域名才会生成配置，天然防滥用。

## 多节点

`nodes` 表登记节点（IP、后缀域、状态）。新节点执行 `deploy/edge/bootstrap.sh` 入网。站点创建时调度到首个 active 节点（后续可扩展容量感知调度）。
